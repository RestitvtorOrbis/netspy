## Decisions and contract

`New-ReleaseArchive.ps1` takes mandatory `-BuildDirectory`, `-OutputDirectory`, `-PackageName` (ValidateSet: `netframework`, `net`, `net-win32`, `net-win64`), and `-SourceCommit` (exact 40 hex characters). It validates a real build directory with `dnSpy.exe`, `bin/dnSpy.Bundles.x.dll`, `bin/dnSpy.Bundles.dll`, `bin/Microsoft.NET.HostModel.Bundle.dll`; fail before archive creation if missing. Create a new `netSpy-<PackageName>.zip` under output, containing the contents of BuildDirectory at archive root. Never mutate input, overwrite an existing zip, or remove an output directory. Use .NET `ZipFile.CreateFromDirectory` with includeBaseDirectory false. Write a sibling `<archive>.sha256` containing lowercase SHA256 plus two spaces plus archive filename, and sibling `<archive>.source.txt` containing source SHA and newline; fail if those existing outputs would be replaced. Return/report the three paths. Package validation is structural; it must not claim to have executed dnSpy.

Replace the current copy-to-C-drive/upload staging steps with this script targeting each existing matrix build-dir and an isolated `artifacts/packages/<package-name>` output directory. Actions artifact names stay unchanged; upload the three package files. Include artifacts on pull requests as well, so reviewers can retrieve tested packages; retain fatal no-files behavior. Preserve historical fixture artifact uploads separately.

Add a `publish-release` job with `needs: [build, historical-bundle-tests, bundle-integration-tests]`, `runs-on: windows-latest`, and job-only `permissions: contents: write`. Default workflow permissions are `contents: read`. Run only for `release` or master push/dispatch, never pull requests or non-master dispatch. Change release trigger from `released` to `published` so published prereleases are covered; do not alter branch push filters.

Download only the four exact product artifact names (four explicit download steps or equivalent exact-name matrix into separate subdirectories), validate exactly one zip/checksum/source triplet per expected variant, verify checksums and every source SHA equals `github.sha`, then write deterministic `SHA256SUMS.txt` (ordinal basename order, lowercase hash, two spaces, basename, LF per line). Reject missing/extra triplet files, duplicate names, incorrect checksum basenames and mismatched source before remote mutation. This combined checksum covers only the four expected zips.

Implement orchestration in `Build/Publish-Release.ps1`, invoked by the workflow with explicit `-EventName`, `-EventAction`, `-Ref`, `-SourceCommit`, `-Repository`, `-RunUrl`, `-ArtifactDirectory`, and release-event `-ReleaseTag`/`-ReleaseId`. Validate event eligibility again in the helper: only master push/dispatch or `release` action `published`; PRs, other actions/events and non-master dispatch must produce no mutating calls. Use environment values/structured arguments; every gh exit code is checked, and API errors are not interpreted as absence.

Before create/edit/upload, perform a complete read-only preflight:

- Resolve tags to their peeled commit (including annotated tags), requiring exact source SHA. For release events require the event repository, release ID and tag to match the fetched release; never substitute an automatic tag. Automatic publication uses `build-<full SHA>`, the master’s title and prerelease flag; existing automatic releases must match those fields. A matching existing tag without a release permits creation; absent automatic tags may be created with `--target <SHA>`, never force-moved. Missing event releases or conflicting target/release identity fail.
- Validate notes using the section contract below. Enumerate all assets and download existing expected assets to isolated temporary files. There are five expected names: four zips and `SHA256SUMS.txt`. Reuse only byte-matching assets (compare downloaded SHA256 against local validated bytes); reject duplicate expected names, case-only aliases or differing bytes, including checksum-file differences, before any mutation. Unrelated assets may remain untouched. Asset downloads/read failures fail closed.
- Re-fetch body, identity and asset inventory immediately before mutation; if changed, restart full preflight against that state or fail without mutation. Serialize publication per repository/tag in workflow concurrency with cancellation disabled; an upload race must fail without clobber and requires another validated retry.

After successful preflight create the missing automatic prerelease, or append notes only if the matching section is absent, then upload only missing expected assets without `--clobber`. A notes-only state, any subset of matching assets (with or without checksum), assets without a marker, or a fully completed matching release can resume: preserve matching state, append the section only if absent, upload missing files, and finish as a no-op if complete. A new run URL alone is not a conflict: preserve valid prior provenance for the same source. Changed rebuilt archive bytes for the same source are a conflict, not a reason to replace assets. Failures leave prior notes/assets intact; the next attempt repeats all checks.

Release notes contain source SHA, `${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}`, variant descriptions (net48 requires .NET Framework 4.8; net requires .NET 10 Desktop Runtime; win32/win64 include runtime), and instructions to extract the complete archive, launch `dnSpy.exe`, open the bundle, expand Assemblies, and select its main DLL/type. Do not claim all methods or third-party packers are supported. Runtime GitHub values go through environment variables/structured arguments, not injected shell code.

Generate one Markdown section delimited by `<!-- netspy-build:<full SHA> -->` and `<!-- /netspy-build -->`, containing the provenance, variant and usage information above. A valid existing section has exactly one opening/closing pair, the expected SHA in both marker and source field, and a workflow run URL for this repository; its variant/usage content must match the generated contract (only the run ID may differ). Reject any other build SHA, mismatched source field, malformed/unclosed/duplicate/nested markers or conflicting section content before notes or asset mutation. An absent section permits append; a matching section is reused byte-for-byte. Preserve all prior body text exactly. Fetch body through `gh release view <tag> --repo <repository> --json body`, parse the exact JSON string, append two newlines and the section (section alone for empty body), and use a temporary notes file with `gh release edit --notes-file`. New automatic prereleases use the section as initial `gh release create --notes-file` content. Never alter an existing release’s title, tag or prerelease flag, truncate prose, duplicate markers or delete assets to make a retry appear fresh.

## Executable orchestration verification

`Build/Test-ReleasePublication.ps1` is a Pester-free, credential-free PowerShell test entrypoint. `Publish-Release.ps1` exposes an injectable `-GhInvoker` scriptblock accepting argument arrays and returning exit code/stdout; the default invokes real `gh`. The workflow never overrides it. Tests supply a stateful fake implementing reads, downloads, create/edit/upload and failures, using temporary synthetic package triplets and release state. Exercise the same production validation/action path, not a parallel simplified validator or source-text assertions. The fake logs all calls and rejects unexpected ones; no token, network or installed gh is required. Verify:

1. Master push/dispatch and published release proceed; PRs, non-master push/dispatch, unpublished/released actions and unrelated events make zero mutations, regardless of supplied artifacts.
2. Absent automatic tag/release creates with exact SHA/title/prerelease; matching lightweight and annotated tags work; wrong peeled commit, event release ID/tag/repository mismatch or missing event release fail before mutation. Read/authentication errors also fail without creation.
3. Four valid triplets produce deterministic checksums; missing/extra/duplicate files, bad hash/basename, wrong source SHA and conflicting remote checksum bytes each cause zero mutations.
4. Empty/nonempty bodies append once and preserve Unicode, CRLF and trailing prose exactly; matching section from an earlier run is unchanged; other SHA, source mismatch, malformed/duplicate markers and wrong-repository run URL reject before mutation. Refetched changed state must be revalidated or rejected.
5. Inject failure immediately after notes edit and after each upload; retry from each saved state reuses matching bytes, uploads only missing files, preserves the original section/run URL and completes. Cover existing assets without marker, existing checksum with missing zip, and fully complete no-op. Assert one marker pair and no clobber/delete/force calls throughout.
6. A conflicting zip, checksum, duplicate expected name or case alias rejects before *any* mutation, even when other assets are missing or notes need appending. Upload failure/race preserves existing state and fails; retry reruns validation. Unrelated assets remain untouched.
