# BLC-004 — Package complete builds and publish GitHub Release downloads

Status: Planned. Dependency: BLC-003. Expected commit: `ci(release): BLC-004 publish validated netSpy build archives`.

## Objective and paths

Deliver downloadable zip assets containing the working bundle extension. Own `.github/workflows/build.yml`, new `Build/New-ReleaseArchive.ps1`, new `Build/Test-ReleasePackaging.ps1`, and `README.md` download instructions. Do not modify `build.ps1`, checked-in binary/icon files, fixture artifact formats, product assembly names, dependencies or signing. Do not upload the user's input executable.

## Decisions and contract

`New-ReleaseArchive.ps1` takes mandatory `-BuildDirectory`, `-OutputDirectory`, `-PackageName` (ValidateSet: `netframework`, `net`, `net-win32`, `net-win64`), and `-SourceCommit` (exact 40 hex characters). It validates a real build directory with `dnSpy.exe`, `bin/dnSpy.Bundles.x.dll`, `bin/dnSpy.Bundles.dll`, `bin/Microsoft.NET.HostModel.Bundle.dll`; fail before archive creation if missing. Create a new `netSpy-<PackageName>.zip` under output, containing the contents of BuildDirectory at archive root. Never mutate input, overwrite an existing zip, or remove an output directory. Use .NET `ZipFile.CreateFromDirectory` with includeBaseDirectory false. Write a sibling `<archive>.sha256` containing lowercase SHA256 plus two spaces plus archive filename, and sibling `<archive>.source.txt` containing source SHA and newline; fail if those existing outputs would be replaced. Return/report the three paths. Package validation is structural; it must not claim to have executed dnSpy.

Replace the current copy-to-C-drive/upload staging steps with this script targeting each existing matrix build-dir and an isolated `artifacts/packages/<package-name>` output directory. Actions artifact names stay unchanged; upload the three package files. Include artifacts on pull requests as well, so reviewers can retrieve tested packages; retain fatal no-files behavior. Preserve historical fixture artifact uploads separately.

Add a `publish-release` job with `needs: [build, historical-bundle-tests, bundle-integration-tests]`, `runs-on: windows-latest`, and job-only `permissions: contents: write`. Default workflow permissions are `contents: read`. Run only for `release` or master push/dispatch, never pull requests or non-master dispatch. Change release trigger from `released` to `published` so published prereleases are covered; do not alter branch push filters.

Download only the four exact product artifact names (four explicit download steps or equivalent exact-name matrix into separate subdirectories), validate one zip/checksum/source triplet per expected variant, verify checksums and every source SHA equals `github.sha`, then write one `SHA256SUMS.txt` for the four zip basenames. For existing release events use the event tag and release. Otherwise create prerelease `build-<full SHA>` with `--target <SHA>`, title and notes defined by the master. Check for an existing tag/release and verify target identity before reuse; never force a tag. Use `gh release create ... --notes-file <file>` and `gh release upload` with the four zips and checksum file; never `--clobber`. Explicitly fail on existing conflicting asset names with instructions to inspect the existing release. A repeated same-commit run may safely stop at that documented collision without altering earlier assets.

Release notes contain source SHA, `${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}`, variant descriptions (net48 requires .NET Framework 4.8; net requires .NET 10 Desktop Runtime; win32/win64 include runtime), and instructions to extract the complete archive, launch `dnSpy.exe`, open the bundle, expand Assemblies, and select its main DLL/type. Do not claim all methods or third-party packers are supported. Runtime GitHub values go through environment variables/structured arguments, not injected shell code.

Generate one Markdown section delimited by the exact opening marker `<!-- netspy-build:<full SHA> -->` and closing marker `<!-- /netspy-build -->`; it contains all provenance, variant and usage information above. For a newly created automatic prerelease, pass this section as initial `--notes-file` content. For the existing release of a `release: published` event, and any existing prerelease found on retry, first perform identity/checksum/asset-collision checks, then fetch the current release body with `gh release view <tag> --repo <repository> --json body` and parse the JSON body's exact string. If the opening marker for this SHA already exists, stop with an explicit provenance-section collision error before changing notes or uploading assets. Otherwise append two newlines and the generated section to the existing body (or use the section alone when the body is empty), write that complete string to a temporary notes file, and call `gh release edit <tag> --repo <repository> --notes-file <file>`. Do not change the release title, tag, prerelease flag, or prior body text. Then upload assets without `--clobber`. Every gh call must check its exit code. Failed retries are reported; never delete prior notes/assets to make a retry appear fresh.

Update README with the repository Releases link, Actions fallback, complete-directory extraction requirement, appropriate x64 self-contained download for the reported Windows x64 case, and the same open/expand/select instructions. Explain that executable name remains `dnSpy.exe` inside netSpy archives.
